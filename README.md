# Infrastructure Provisioning & Configuration (Yandex Cloud & Ansible)

Профессиональный DevOps-проект для автоматического развёртывания базовой инфраструктуры в Yandex Cloud с помощью Terraform и последующей конфигурации сервера средствами Ansible. Проект разворачивает изолированную сеть, виртуальную машину Compute Cloud и запускает в Docker контейнеры Grafana и n8n.

## Возможности

- 🏗️ IaC подход: Автоматическое создание VPC-сети и подсети в указанной зоне доступности.
- 🔒 Безопасность: Использование Security Groups с минимально необходимыми правилами (SSH, веб-трафик, ICMP).
- 🔑 Инициализация: Автоматическая настройка пользователя и SSH-ключей на ВМ через cloud-init.
- ⚙️ Авто-инвентарь: Terraform самостоятельно генерирует `hosts.ini` для Ansible сразу после создания ВМ.
- 🚀 Конфигурация: Автоматическая установка Docker, Docker Compose и запуск стека приложений (Grafana, n8n) одной командой Ansible.
- 🔐 Zero Secrets: Полное отсутствие хардкода токенов или ключей в репозитории.

## Структура проекта

infrastructure-provisioning/
├── ansible/
│   ├── docker-compose.yml      # Шаблон контейнеров (Grafana, n8n) для удаленного сервера
│   ├── playbook.yml            # Сценарий Ansible для настройки ОС и запуска Docker-стека
│   └── hosts.ini               # Динамический инвентарь (генерируется Terraform, в Git не попадает)
├── .gitignore                  # Исключает секреты, tfstate, .terraform и hosts.ini
├── versions.tf                 # Фиксация версий Terraform и провайдера
├── providers.tf                # Настройка провайдера Yandex Cloud
├── variables.tf                # Объявления всех переменных проекта
├── main.tf                     # Описание сетевых ресурсов, правил безопасности и ВМ
├── outputs.tf                  # Вывод данных инфраструктуры и генерация файла для Ansible
├── terraform.tfvars.example    # Шаблон для заполнения переменных окружения
└── README.md                   # Этот файл

## Требования

- Terraform >= 1.5.0
- Ansible >= 2.10 (на локальной машине управления)
- Аккаунт и платежный аккаунт в Yandex Cloud

## Быстрый старт

### 1. Настройка аутентификации

Провайдер использует переменные окружения для авторизации. Задайте OAuth-токен в терминале:

```bash
export YC_TOKEN="<ваш_OAuth_токен>"
```

### 2. Настройка переменных

Скопируйте шаблон конфигурации переменных:

```bash
cp terraform.tfvars.example terraform.tfvars
```

Отредактируйте созданный `terraform.tfvars`, указав свои `cloud_id`, `folder_id` и путь к публичному SSH-ключу. 

> ⚠️ Файл `terraform.tfvars` содержит конфиденциальные данные, заблокирован в `.gitignore` и никогда не попадет в публичный репозиторий.

### 3. Развертывание инфраструктуры (Terraform)

Инициализируйте проект и примените конфигурацию:

```bash
terraform init      # Скачивание провайдера yandex-cloud
terraform plan      # Проверка плана создаваемых ресурсов
terraform apply     # Создание сети, Security Group, ВМ и генерация инвентаря Ansible
```

В конце работы Terraform выведет публичный IP-адрес вашей машины и автоматически создаст файл `ansible/hosts.ini`.

### 4. Конфигурация и запуск приложений (Ansible)

Подождите около 30 секунд, пока операционная система на виртуалке запустится, перейдите в папку Ansible и запустите плейбук:

```bash
cd ansible
ansible-playbook -i hosts.ini playbook.yml
```

Ansible автоматически подключится к созданному серверу по SSH, обновит пакеты, установит Docker, Docker Compose, скопирует файлы конфигурации и запустит контейнеры Grafana и n8n в фоновом режиме.

### 5. Проверка работы

После успешного выполнения плейбука сервисы станут доступны по публичному IP-адресу вашей виртуальной машины:
- Grafana: `http://<публичный_IP_ВМ_из_outputs>:3000`
- n8n: `http://<публичный_IP_ВМ_из_outputs>:5678`

### 6. Уничтожение ресурсов

Если инфраструктура больше не нужна, её можно удалить одной командой:

```bash
terraform destroy
```

## Описание файлов проекта

| Файл / Каталог | Назначение |
|------|------|
| `ansible/playbook.yml` | Автоматизирует установку Docker-движка и деплой compose-сценария. |
| `ansible/docker-compose.yml` | Описывает конфигурацию изолированных контейнеров для Grafana и n8n. |
| `versions.tf` | Задает требования к минимальной версии ядра Terraform и зеркала провайдера. |
| `providers.tf` | Настраивает инициализацию облачной платформы Yandex Cloud. |
| `variables.tf` | Задает типизацию, дефолтные значения и описания для параметров проекта. |
| `main.tf` | Основной манифест: строит топологию сети, группы безопасности и параметры Compute инстанса. |
| `outputs.tf` | Формирует выходные логи и отвечает за создание локального конфигурационного файла для Ansible. |
| `.gitignore` | Исключает из индексации Git кэш Terraform, файлы состояний (`.tfstate`) и динамические хосты Ansible. |

## Безопасность

- Все чувствительные данные передаются через переменные окружения среды.
- Сгенерированный файл `ansible/hosts.ini` содержит публичный IP-адрес хоста и путь к вашему приватному ключу, поэтому он строго изолирован в `.gitignore`.
- Рекомендуется изменить переменную `ssh_allowed_cidr` в `variables.tf` со значения `0.0.0.0/0` на ваш конкретный белый IP-адрес для защиты порта SSH от брутфорса.
